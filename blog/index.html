GeoServer Security Update - November 2026

Nov 23, 2026 • Jody Garnett

This post provides details on the vulnerabilities addressed by the October releases, now that CVEs have been assigned and the security advisories published.

If you are responsible for a GeoServer instance, the short version is: please update to GeoServer 3.0.2, GeoServer 2.28.6, or GeoServer 2.27.7.

The GeoServer project follows a coordinated vulnerability disclosure policy: vulnerabilities are fixed for both stable and maintenance releases, prior to vulnerability details being published. The goal is to give everyone an opportunity to update prior to public disclosure.

Thanks to everyone for waiting patiently as CVE numbers are assigned (and to Jonathan and Shelby for prioritizing our CVE Numbering Authority requests).

October releases

GeoServer 3.0.2, GeoServer 2.28.6, and GeoServer 2.27.7:

  • CVE-2026-120701 Unauthenticated SSRF via WPS gs:DownloadMap (High, WPS Download extension)
  • CVE-2026-120706 Unauthenticated SSRF and file read via WPS inline VRT to native GDAL (High, WPS extension)
  • CVE-2026-120704 Remote code execution via SQLite JDBC extension loading in JDBC security services (High)
  • CVE-2026-120710 Arbitrary file write via GeoWebCache FileRasterFilter ZIP update (High)
  • CVE-2026-120707 GeoFence source IP rules bypass via X-Forwarded-For (High, GeoFence extension)
  • CVE-2026-120708 ACL source IP rules bypass via X-Forwarded-For (High, ACL plugin)
  • CVE-2026-120703 JWT Headers roles header trusted without validation (High, community module)
  • CVE-2026-120709 Unauthenticated SSRF and file read via printing legend icon URL (Medium, printing extension)
  • CVE-2026-129244 WFS stored query exception discloses data directory path (Medium)
  • CVE-2026-129240 Local file probing via file:// schemaLocation during strict schema validation (Medium)
  • CVE-2026-120702 CSW DirectDownload served for layers where it is disabled (Medium)

  • CVE-2026-129245 Predictable remember-me key allows administrator session forgery (Critical)

    This vulnerability was initially reported as step 4 of a chain leading to remote code execution. At the direction of the CVE Numbering Authority the other steps were each assigned their own CVE number:

    1. CVE-2026-129244: WFS stored query exception discloses data directory path (Medium)
    2. CVE-2026-129243: Service security rules bypassed with a prefixed service name such as x/WFS (High)
    3. CVE-2026-120705: Unauthenticated WFS GetFeatureById XML injection (High)
    4. CVE-2026-129245: Predictable remember-me key allows administrator session forgery
    5. CVE-2026-129242: Deserialization in JDBC user and role services allows administrator code execution (High)

  • CVE-2026-129294 Unauthenticated style management in OGC API Styles (High, community module)
    This vulnerability was initially reported as step 1 of a chain leading to XSS:

    1. CVE-2026-129294: Unauthenticated style management in OGC API Styles
    2. CVE-2026-129293 Stored XSS via style name in style editor Layer Preview (High)

The use of the CVE system allows the GeoServer team to reach a wider audience than blog posts.

Previous Releases

The following vulnerabilities were addressed in earlier releases, and are now published.

GeoServer 3.0.0, GeoServer 2.28.4, and GeoServer 2.27.6:

  • CVE-2025-53607 Unauthenticated XXE file read and SSRF via xsi:schemaLocation in OWS requests (High)

GeoServer 3.0.0, GeoServer 2.28.5, and GeoServer 2.27.6:

  • CVE-2024-35233 ImageMosaic remote code execution via REST coverage store file upload (High)

Thanks

Thanks to everyone who reported these vulnerabilities, and to the geoserver-security team members who verified, fixed, and backported each issue. Individual credits are listed on each security advisory.

Q: How can I help?

If your organization depends on GeoServer, please consider sponsoring the project, or have your staff directly participate in geoserver-security work.

Q: How often should I upgrade GeoServer?

GeoServer operates with a time-boxed release cycle, maintaining “stable” and “maintenance” releases, over the course of a year.

  • GeoServer 3.0.x is the current stable release
  • GeoServer 2.28.x is the current maintenance release

Please upgrade to a supported release at least once a year to continue receiving security fixes. See the Upgrading existing versions (User Guide) for guidance.

Q: How do I report a vulnerability?

Please see our security policy for instructions on reporting vulnerabilities privately using GitHub security advisories.

Java4Shell (CVE-2026-114938): add one Java flag to GeoServer today

Nov 18, 2026 • Andrea Aime

A critical vulnerability in the Java runtime became public on 17 November 2026. It goes by the name Java4Shell (CVE-2026-114938), and it is a memory corruption bug in the accelerated Base64 decoder of the Java virtual machine.

The bug is in Java, not in GeoServer, but every server application that runs on an affected Java inherits it. The good news is that the fix is easy, safe and quick: one Java flag switches off the affected code.

-XX:-UseBASE64Intrinsics

Add the flag to the Java options and restart GeoServer, nothing else is needed. It works with every GeoServer version, and GeoServer, its configuration and its data directory stay as they are. If you run a GeoServer, please do it today.

Public reports name Java 17.0.6 and newer, Java 21 and Java 25, on x86-64 processors with the AVX-512 VBMI instruction set, and Oracle also lists a Java 8 build, 8u511b33-perf. These reports are one day old and the list keeps changing. At the time of writing they mention no attacks in the wild, so there is time to act calmly, and no reason to wait. Even if your Java version, processor or architecture might not be affected, we recommend applying the flag anyway: it is safe everywhere, and it covers you if a later report extends the list.

Adding the flag

The flag is a Java startup option, so it goes wherever the installation sets its Java options. One way works for any setup: the JAVA_TOOL_OPTIONS environment variable, which Java reads at startup (if the variable already has a value, append the flag to it). Restart GeoServer after the change.

A few examples:

  • Binary package: run export JAVA_OPTS="$JAVA_OPTS -XX:-UseBASE64Intrinsics" before bin/startup.sh.
  • Tomcat: add CATALINA_OPTS="$CATALINA_OPTS -XX:-UseBASE64Intrinsics" to bin/setenv.sh.
  • Official GeoServer Docker image (docker.osgeo.org/geoserver): add -e JAVA_TOOL_OPTIONS=-XX:-UseBASE64Intrinsics to docker run.

Some Java 8 builds do not know the flag and stop at startup with the message Unrecognized VM option 'UseBASE64Intrinsics'. Such a build does not include the accelerated decoder, so this vulnerability cannot be used against it. In that case remove the flag and start GeoServer again.

Checking that the flag is active

The check depends on what GeoServer runs on: a full JDK, or a JRE.

With a JDK

The JDK includes jinfo, a tool that asks the running JVM for the value of the flag. On Linux and macOS, for the binary package:

jinfo -flag UseBASE64Intrinsics $(pgrep -f 'start\.jar' | head -1)

For Tomcat:

jinfo -flag UseBASE64Intrinsics $(pgrep -f 'org\.apache\.catalina\.startup\.Bootstrap' | head -1)

On Windows, run jps -l to find the process id of GeoServer, then pass it to jinfo:

jinfo -flag UseBASE64Intrinsics PID

Run the commands as the operating system user that runs GeoServer, for example with sudo -u tomcat in front when Tomcat runs as the tomcat user. jinfo prints one line:

  • -XX:-UseBASE64Intrinsics (minus sign): the flag is active.
  • -XX:+UseBASE64Intrinsics (plus sign): the flag is missing and the JVM might be vulnerable. Check the startup options, restart, then run the command again.

With a JRE

A JRE has no jinfo, so the check looks at how the Java process was started. On Linux, replace PID with the process id of GeoServer:

cat /proc/PID/cmdline /proc/PID/environ | tr '\0' '\n' | grep -o '[^ ]*UseBASE64Intrinsics'

A line with -XX:-UseBASE64Intrinsics means the flag is there. No output means the flag is missing.

On Windows, PowerShell lists the command line of the Java processes:

Get-CimInstance Win32_Process -Filter "Name = 'java.exe'" | Select-Object ProcessId, CommandLine

The command line shows the flag when it comes from the Java options. When it comes from JAVA_TOOL_OPTIONS, look at the console output instead: on every operating system, Java starts it with the line Picked up JAVA_TOOL_OPTIONS: -XX:-UseBASE64Intrinsics.

After the flag

The flag only tells Java to use its standard Base64 decoder in place of the accelerated one, so GeoServer works as before and we expect no visible change in performance. It is a mitigation though, and the permanent fix is a Java update.

At the time of writing, several widely used OpenJDK distributions, such as Eclipse Temurin and the packages of the main Linux distributions, do not have a patched build yet. Update Java as soon as the vendor of your distribution has one (the vendor advisory gives the exact version number). After the update the flag can stay in place, or be removed.

If something is unclear, ask on the user forum. Security issues go through the GeoServer security policy, as usual.

GeoServer 3.0.2 Release

Oct 19, 2026 • Jody Garnett

GeoServer 3.0.2 release is now available with downloads (bin, war, windows), along with docs and extensions.

This is a stable release of GeoServer recommended for production use. GeoServer 3.0.2 includes the latest GeoTools 35.2, GeoWebCache 2.0.2, along with mapfish-print-v2 2.5.2 and ImageN 0.9.3. There is a new GeoServer Cloud 3.0.2 release - representing the first time an updated GeoServer Cloud is made available on release day.

OGC API Maps 1.0

The OGC API Maps community module has been aligned with the final OGC API - Maps 1.0.0 standard.

  • Dataset map: Draw several collections into a single map, choosing and ordering them with the collections parameter. The map preview provides a palette to select collections, the first one drawn at the bottom.

  • Filtering: Maps can be filtered using CQL2 Text, CQL2 JSON or ECQL, using the queryable attributes of each collection.

  • Conformance: Each optional conformance class (subsetting, scaling, background, crs, output formats, and more) can be enabled or disabled from the Services > Mapping settings page. Invalid parameters are now reported as a bad request rather than an internal error.

For more information see OGC API Maps in the user manual.

Thanks to Andrea Aime (GeoSolutions) for the OGC API - Maps development, and Jody Garnett (GeoCat) for the 3.0.x backport and improvements to the conformance table editor.

GeoFence for GeoServer 3

The GeoFence extensions are now available for GeoServer 3, completing Milestone 4: Integration of the GeoServer 3 crowdfunding campaign.

GeoFence has been updated to Jakarta EE, Spring Framework 7 and Hibernate 7:

  • The geofence plugin now communicates with a standalone GeoFence server using REST, as Spring remoting is no longer available.
  • The embedded geofence-server requires a PostgreSQL / PostGIS database, H2 is no longer supported.
  • The GeoFence admin page is found under the Security menu, showing the active engine and GeoFence services URL.

Existing GeoFence users should review the migration guide before upgrading, as the datasource configuration file has been renamed and the GeoFence authentication provider has been removed.

Thanks to Emanuele Tajariol (GeoSolutions) for this work, and to the GeoServer 3 crowdfunding sponsors for making it possible.

FIPS

GeoServer 3.0.2 comes with a new FIPS community module. FIPS 140-3 is a United States government standard for cryptography modules, and many federal agencies and their suppliers are only allowed to run software that uses a validated one. In summary:

  • The FIPS module replaces the regular BouncyCastle library with the FIPS-validated one and runs it in approved-only mode.
  • Passwords are stored with AES-GCM.
  • A new FIPS tab under Server Status shows the overall cryptographic setup (see screenshot below).

Keep in mind that the module works on Linux only and needs a new data directory: there is no migration tool yet for an existing one.

  • GEOS-12178 FIPS community module
  • GEOS-12123 Login failure in FIPS mode for GeoServerDigestPasswordEncoder

Thanks to Andrea Aime (GeoSolutions) for the FIPS module development.

GeoServer 2.27.7 Release

Oct 19, 2026 • Jody Garnett

GeoServer 2.27.7 release is now available with downloads (bin, war, windows), along with docs and extensions.

This series has previously reached end-of-life, with this release issued to address an urgent bug or security vulnerability. Please apply this update as a mitigation measure only, and plan to upgrade to a stable or maintenance release of GeoServer.

GeoServer 2.27.7 is made in conjunction with GeoTools 33.7.

Thanks to Peter Smythe (AfriGIS) for making this release, and Andrea Aime (GeoSolutions) for testing.

Security Considerations

This release addresses security vulnerabilities and is an important upgrade for production systems.

  • CVE-2026-120705 Unauthenticated WFS GetFeatureById XML injection (High)
  • CVE-2026-120701 Unauthenticated SSRF via WPS gs:DownloadMap (High, WPS Download extension)
  • CVE-2026-120706 Unauthenticated SSRF and file read via WPS inline VRT to native GDAL (High, WPS extension)
  • CVE-2026-129243 Service security rules bypassed with a prefixed service name such as x/WFS (High)
  • CVE-2026-129242 Deserialization in JDBC user and role services allows administrator code execution (High)
  • CVE-2026-120704 Remote code execution via SQLite JDBC extension loading in JDBC security services (High)
  • CVE-2026-120710 Arbitrary file write via GeoWebCache FileRasterFilter ZIP update (High)
  • CVE-2026-129293 Stored XSS via style name in style editor Layer Preview (High)
  • CVE-2026-120707 GeoFence source IP rules bypass via X-Forwarded-For (High, GeoFence extension)
  • CVE-2026-120708 ACL source IP rules bypass via X-Forwarded-For (High, ACL plugin)
  • CVE-2026-129294 Unauthenticated style management in OGC API Styles (High, community module)
  • CVE-2026-120703 JWT Headers roles header trusted without validation (High, community module)
  • CVE-2026-129240 Local file probing via file:// schemaLocation during strict schema validation (Medium)
  • CVE-2026-120709 Unauthenticated SSRF and file read via printing legend icon URL (Medium, printing extension)
  • CVE-2026-129244 WFS stored query exception discloses data directory path (Medium)
  • CVE-2026-120702 CSW DirectDownload served for layers where it is disabled (Medium)

The use of the CVE system allows the GeoServer team to reach a wider audience than blog posts.

It is worth repeating that the 2.27 series has reached end-of-life. While we understand that this is the last series supporting Java 8 please update to the supported 2.28 or 3.0 releases.

See project security policy for more information on how security vulnerabilities are managed.
